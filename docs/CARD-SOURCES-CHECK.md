# Gwent card sources: database cross-check

Status: audit only, generated by `tools/gamedb/card_check.py`. Nothing in `data/` or `tools/` is changed by this report. The proposed changes at the end are for the reviewer to accept or reject.

## What was compared

Each of the 224 cards in `data/gwent_cards.json` (202 main collectible cards, 22 leaders; the 4 summon-only tokens are excluded there and here) was matched to the game database `db/w3db.sqlite` (opened read-only). The database sources are derived from the raw game data without using the reviewed `source` field. They are then compared with that reviewed source.

Database sources counted for a card:

- `vendor`: a `loot_entries` row for the card item in a loot table whose name starts with `_store__` or contains `store` or `shop`.
- `container`: any other loot table that holds the card item (quest card lockers, unique chests and so on).
- `quest_reward`: a `reward_items` row for the card item, and a `CQuestRewardBlock` in a quest graph that names that reward. `reward_unplaced` is a reward that no graph block uses.
- `graph_ref`: a non-test quest-graph node (for example a `CQuestScriptBlock` grant) whose properties or comment name the card item. Test and condition classes (`CQCHasItem`, `W3QuestCond_IsItemQuantityMet`, `CQuestConditionBlock`, `CQuestPauseConditionBlock`) are not sources.
- Opponent decks are not sources. A named opponent's deck that holds the card (deck name prefix before `#` in `gwent_deck_cards`) is reported per card as weak evidence, as `card_sources.json` itself labels it ("opponent evidence, not a proven reward"). Faction, AI difficulty, tutorial and tournament decks are generic and are not listed.
- `leader_deck`: for a copper leader only, the generic faction default deck whose `leaderCard` is that leader (the reviewed `deck_default`). A leader's appearance in a named opponent's deck is opponent evidence, like a player deck.

Loot tables from the test file `def_loot_test.xml` are excluded from the sources and listed in the notes.

## How cards were mapped to items

The database has no card index on items. Each card's item name is found by trying these rules in order and taking the first that exists in the database (`items`, `loot_entries`, `reward_items` or a quest-graph literal):

1. `item_attr`: the `item` attribute of the card's `gwent_cards` row, matched by `card_index` to the card's `index` in `data/gwent_cards.json`.
2. `internal_name`: `gwint_card_` plus the card's `internal_name`.
3. `gog_name`: for `...GOG` internal names, `gwint_card_gog_` plus the base name.
4. `deck_default_only`: the copper leader of each faction is the deck default. Its `gwint_card_<base>_*` siblings are the collectible leader cards, which have their own rows, so the copper leader takes only its deck-default evidence and no item sources.

Cards with no item name in the database are listed in the Not resolved section. For them the database can still show a deck or a graph mention, but no shop, container or reward.

Classes: `agree` means the reviewed source is among the database sources and nothing else is found. `db_more` means the reviewed source is confirmed (or the reviewed source is `unknown`) and the database shows more counted sources. `reviewed_only` means the reviewed source is not found in the database. `no_db_source` means the database finds nothing for the card at all.

Opponent decks never move a card between classes; see the Gwent players section.

Note on `unknown` reviewed sources: they are classed `db_more` when the database finds a source, because the database then supplies the source the review lacks. Their classification is a judgement and is marked in the table.

Window kinds in `data/gwent_cards.json`: 32 cards have a window other than `none` (18 one_time and 14 missable). The brief asked for 18; the file has 18 one-time plus 14 missable, so all 32 are listed.
